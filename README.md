# Autonomous AI-Powered Incident Commander

A local full-stack incident response prototype for exploring simulated SRE scenarios. It provides an incident overview, evidence trails, reference runbooks, human-approved simulated remediation, simulated recovery checks, and synthetic postmortems.

## Safety and scope

- All seeded incidents, service metrics, histories, and generated postmortems are explicitly labeled synthetic.
- No production telemetry or infrastructure is connected.
- Remediation only records a simulated operator decision and a simulated recovery result. It does not execute infrastructure changes.
- The operational knowledge layer uses local BM25 retrieval by default. An optional embeddings provider enables semantic retrieval; no generative answer-writing model is connected. Investigation guidance remains deterministic scenario data.

## Requirements

- Node.js 20 or newer
- Python 3.12

## Run in Replit

The `Start application` workflow runs Vite on port 5000 and FastAPI on port 8000. Vite proxies `/api` requests to FastAPI. Replit installs the project packages from `package.json` and `requirements.txt`.

```bash
npm run dev
```

The frontend is served on port 5000; the API is available through the frontend proxy at `/api`.

For local development outside Replit, use Node.js 20+ and a standard Python 3.12 installation:

```bash
npm install
python -m pip install -r requirements.txt
npm run dev
```

## Configuration and data

Copy `.env.example` to `.env` to override optional settings. `INCIDENT_DATABASE_URL` defaults to a local SQLite file at `backend/data/incident_commander.db`; tables are created and synthetic demonstration records are seeded on first startup. Keep `.env` private; it is excluded from version control.

The backend exposes `/api/health`, `/api/dashboard`, incident creation and investigation endpoints, service summaries, runbook search, approval/rejection and recovery simulation endpoints, and synthetic postmortem generation. Interactive API documentation is available at `/docs` on the FastAPI server.

## Checkout incident demo

The **Checkout Simulation** view uses a deterministic, synthetic-only scenario across API Gateway, Checkout Service, Order Service, and Database Service. Start a run to replay a healthy baseline, a simulated deployment that reduces `DB_POOL_SIZE` from 50 to 10, increased traffic, and the resulting pool exhaustion, timeouts, latency, and errors. Metric values and event order repeat on each run; timestamps are generated by the backend.

The API is available at `/api/simulation/metrics`, `/api/simulation/health`, and `/api/simulation/events`. Start or reset a run with `POST /api/simulation/start` or `POST /api/simulation/reset`. Reset removes only generated records for the dedicated checkout demo services. The simulator does not call or modify external services or infrastructure.

## Operational knowledge base

The workspace seeds seven clearly labelled synthetic references: Checkout Service Runbook, Database Connection Pool Troubleshooting Guide, Architecture Overview, Deployment #1842 Change Record, Historical Incident INC-873, Incident Severity Policy, and Standard Rollback Procedure. Uploaded documents and overlapping passage chunks are stored in the same local SQLite database.

- `GET /api/knowledge/documents` lists the source documents and their approval/indexing status.
- `POST /api/knowledge/documents` accepts UTF-8 Markdown (`.md`, `.markdown`) or text (`.txt`) multipart uploads up to 1 MB. The caller must submit an approval confirmation, approver name, and source attribution.
- `GET /api/knowledge/search?q=...` returns ranked passages with document title, source, excerpt, and retrieval mode.
- `GET /api/knowledge/documents/{id}` previews a source; `GET /api/knowledge/documents/{id}/chunks/{chunk_index}` retrieves a passage.
- `GET /api/knowledge/status` reports document/chunk counts, supported formats, and the active retrieval mode.

Keyword search uses an in-process BM25 implementation and works without external services. Semantic retrieval is optional and uses an OpenAI-compatible embeddings endpoint when all three settings are configured: `RAG_EMBEDDING_API_URL`, `RAG_EMBEDDING_API_KEY`, and `RAG_EMBEDDING_MODEL`. Add the key through Replit Secrets; never commit it or put it in source control. Configured embeddings are stored with passage chunks in SQLite and used for cosine-similarity retrieval. If a configured provider fails or its vector dimensions change, the API reports an error rather than claiming semantic results.

PDF uploads are not supported. The application has no authentication or verified approval system, so upload approval and approver identity are recorded from the submitting operator but are not independently verified. Retrieved text is reference material only: it cannot approve or execute actions. The existing remediation controls remain human-approved simulations.
